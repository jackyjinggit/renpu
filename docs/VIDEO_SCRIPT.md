# 仁谱 视频脚本 · 5 分钟演示走查

> 录制提示：按下面时间码 + 配音用 cue 顺序录，可分段/合并。
> 屏幕录制建议 OBS / Windows Game Bar / QuickTime（macOS）。
> 终端字体推荐：Sarasa Mono / Cascadia Code / 等宽 16-18pt。

---

## 0:00 · 开场（30 秒）

**画面**：终端黑屏，背景写"FORK PERSONAL AI · 仁谱"。

**配音**：
> 这是一个叫 仁谱 的人际关系中枢。
> 你应该有过这种感觉：问自己「我跟 XXX 什么关系来着？」
> 然后发现……记不清。要么搜不到，要么翻了半小时聊天记录才想起来。
> 仁谱 是给你的「人脉 OS」——你的微信联系人，会变成一个你能问、能写、能接的本地库。
> 现在看它怎么跑。

**操作**：黑屏不操作。

---

## 0:30 · 安装 & 启动（45 秒）

**画面**：终端。

**配音**：
> 一句话从零跑起来。

**操作**（高亮每条命令）：
```bash
pip install pycryptodome          # 装依赖（30 秒）
renpu doctor                        # 自检 — 应看见一切就绪
renpu init                          # 建库
renpu ingest --demo                 # 灌 demo 数据（无微信库也能体验）
```

**配音叠加**：
> 看——没有任何配置。一行 demo 数据直接灌进去，立刻可查。

**画面切**：翻到 `renpu doctor` 的输出，高亮「✅ 一切就绪」一行。

---

## 1:15 · 查人（30 秒）

**画面**：终端。

**配音**：
> 随便查一个人。

**操作**：
```bash
renpu who 林夏
```

**画面切**：屏幕定格在 who 输出——单人档案：基本信息 + 近期对话 + 群共现 + 关系边 + 待办 + 事件。

**配音**：
> 这一坨输出，就是「我跟这个人什么关系」的全集。
> 不再翻聊天记录，不再凭印象。

---

## 1:45 · 全局视角（30 秒）

**画面**：终端。

**配音**：
> 不只查单个人，看一下全局：

**操作**：
```bash
renpu people --days 7              # 近 7 天活跃
renpu edges --limit 5              # 人际边（谁跟谁强相关）
```

**画面切**：两个命令的输出。

**配音**：
> 这个 dashboard 不只是好用——它**可被任意 agent 调用**。

---

## 2:15 · 起 API（30 秒）

**画面**：两个终端 / split screen。

**配音**：
> 起一个本地 HTTP API。任何 agent（Claude、Codex、你自己写的脚本）都能通过这个口问。

**操作**：
```bash
# 窗口 1
renpu serve --port 8877

# 窗口 2
curl "http://127.0.0.1:8877/api/who?name=林夏" | jq
curl "http://127.0.0.1:8877/api/people?days=30" | jq
curl "http://127.0.0.1:8877/api/search?q=demo" | jq
```

**画面切**：三个 curl 的返回值。

**配音**：
> 三个端点全用 JSON。任何会话型 AI 都能挂上这个，让它能回答「我跟他什么关系」这个问题。

---

## 2:45 · 写回 / 自我进化（30 秒）

**画面**：终端。

**配音**：
> 数据不只能读，能写。

**操作**：
```bash
renpu note "AAA 同学 · 已能约饭" --name 林夏 --kind ai_note
renpu note "下周一回访确认 demo" --name 苏见白 --todo
renpu todo
```

**配音**：
> 这是给未来的你和未来的 agent 写的笔记。
> 关系会变、事件会忘——但写回 仁谱 之后，下次任何窗口打开，背景一致。

---

## 3:15 · 接真微信（30 秒）

**画面**：终端 + 一个配置编辑展示。

**配音**：
> demo 玩法只是检验产品。接你真微信：
> 1. 找到你的微信 db_storage 路径；
> 2. 拿到 db_key.txt；
> 3. 写一行 config。

**操作**：
```bash
# 编辑 %LOCALAPPDATA%\renpu\config.json
{
  "wc_live": "D:\\...\\db_storage"
}

renpu doctor                     # 现在显示 wc_live ✅
renpu ingest --pull              # 30-90 秒 · 自动解密拉新
renpu stats                      # 看到从 demo 的 10 人 升到 2 万人
```

**配音**：
> 同一条 CLI 同一条 schema 同一条 API。
> 微信 source 只是其中一个 adapter，以后想加飞书、邮件——加个 adapter 就行。

---

## 3:45 · 关掉 demo，改读真库（15 秒）

**画面**：终端。

**配音**：
> demo 数据和真数据可以共存——不同 source 在 DB 里都有 `sync_log` 审计。
> 这里有个小细节：

**操作**：
```bash
renpu sync --days 30 --pull
```

**配音**：
> 默认 ingest 只跑默认 source（wechat），如果你想再灌 demo，加 `--demo`。
> 幂等已保证，重跑不膨胀。

---

## 4:00 · 设计取舍（30 秒）

**画面**：terminal 输出 + highlight overlay。

**配音**：
> 几个故意的取舍：
> 1. **绑 127.0.0.1**——不能让你的 CRM 数据裸奔到外网；
> 2. **判断位不自动填**——tier/circle/org 是你和别人的判断位，程序不替你说；
> 3. **缺口不吞**——语音是加密字节，未读到就如实说未读到；
> 4. **给用户看的显示用昵称+微信号**——wxid 那串只在 DB 里有意义，微信也不能搜。

**画面切**：四个项目四次切画面。

---

## 4:30 · 收尾（30 秒）

**画面**：标题 + GitHub URL。

**配音**：
> 仁谱 v0.1 · 5 分钟装好。
> Apache-2.0 · 蒋平 · GitHub 上找 jackyjinggit。
> demo 先跑 ——
> 再决定要不要接你真微信。
> 它是产品——但你是最终裁判。

**画面**：黑屏收尾。

## 附录 · 录制检查清单

录完前对照这个表：

- [ ] 0:30-1:15 安装那段是否清晰？pip 装慢可能超时（前置提前装）
- [ ] doctor 输出能看清？终端字体太小会糊
- [ ] curl 输出有排版？建议管道加 `| jq` 或 `| python -m json.tool`
- [ ] 没出现 wxid？任何对外露出的字符串都得是「nick + 微信号」
- [ ] 录音：环境安静，每段配音之间 0.5-1 秒停顿
- [ ] 时长：5 分钟以内？太长会让看的人关掉
