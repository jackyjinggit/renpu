人脉的谱系

把你的微信记录变成一张「人」的图谱 —— 谁是谁的人、在哪些群共现、 答应过什么、上次聊到哪里。
本地优先，数据不出本机；任何 agent 都能查、能写。

一眼看懂

关系谱不是消息流

消息流回答「今天要回谁」，关系谱回答「他是谁的人」。 后者只能从结构里长出来——两个人在几个群里一起出现过，就是一条边。

关系图谱示例 · 节点大小 = 共现强度 · 连线粗细 = 共同出现的群数 · 全部数据在本机生成
核心能力

五件事

🕸

关系谱自动建图

两人共同出现在 N 个群 → 一条权重 N 的边。不需要手动整理，摄取时就算出来。

👤

一人一档

基本档案 + 近期对话 + 所在群 + 关系边 + 待办 + 关键事件，一屏看完。

✍

结论可写回

agent 看完对话的判断写回 event/todo 表，每条带原话引用，可溯源。

🔌

双入口

🔒

数据不出本机

库落在你自己的目录，源库全程只读。PII 入库自动脱敏，不上云。

渠道无关

微信只是第一个 adapter。要接飞书或邮件，写一个文件即可，上层零改动。

renpu edges

定位

和「微信日报工具」的区别

市面上有做得不错的同类项目，它们回答「今天有什么该做」。 仁谱回答另一个问题：「他是谁的人」。两者不冲突，可以并存。

仁谱 Renpu情报日报类工具
核心对象人（关系）消息（情报）
主输出关系谱 + 事件 + 待办日报 HTML + 商机清单
查「X 是谁」档案 + 群 + 关系边只能捞出 X 说过的话
关系推理群共现自动建图无
跨渠道统一人实体已预留（同一人多渠道合并）按会话切片
边界

它不做什么

不是云服务库全程在你自己的机器上，不上传、不建账号。
不改你的微信源库全程只读，解密快照落在仁谱自己的目录。
不替你判断「他是什么人」的字段留给你和人工，程序不自动填。
不装懂语音、撤回如实说「未读到」，不假装读懂了。
